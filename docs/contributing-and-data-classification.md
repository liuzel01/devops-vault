# 贡献与数据分类规范

## 提交前检查

所有提交必须保持 Markdown 可读、链接可解析，并运行：

```bash
node scripts/validate.mjs
```

生成型修改还必须在 PR 中说明资料来源、使用的 skill/模型版本、人工核验项和目标文档路径。任何脚本或 Agent 均不得直接向 `main` 推送。

## 数据分类

| 分类 | 允许提交到本仓库 | 要求 |
| --- | --- | --- |
| 团队可共享知识 | 是 | 来源清楚、可由团队成员访问 |
| 个人私密笔记 | 否 | 置于独立私有 Vault 或本机受控目录 |
| 生产运维证据 | 可提交脱敏完整归档、摘要或引用 | 保留团队复盘所需的链路、验证和回滚证据；账号、凭证与高攻击面资源标识必须替换为具名变量 |
| 密钥与身份材料 | 否 | 保存在受控密钥系统，不得进入 Git 历史 |

严禁提交密码、API Token、私钥、证书私钥、云访问密钥、未脱敏生产配置、客户数据或完整敏感日志。发现疑似泄露时，立即停止传播并按团队安全流程撤销相关凭据；仅删除文件不能消除 Git 历史中的泄露风险。

### 脱敏完整归档

脱敏归档存放于 `sources/`，用于保留证据链，不替代易读的 `reviews/` 结论。可保留域名、公开路径、非敏感资源名称、拓扑、命令形态、状态码和排障过程；不得保留账号 ID、密码、Token、私钥、访问密钥，或会显著扩大攻击面的精确 ARN、集群 endpoint、受控资源 ID。

使用具名变量替换被移除的值，例如 `<AWS_ACCOUNT_ID>`、`<AWS_PROFILE_NAME>`、`<CMS_INSTANCE_ROLE_ARN>`、`<EKS_CLUSTER_ARN>`，避免使用无上下文的 `***`。每个归档必须声明 `source_kind`、`redaction` 和 `reviewed_by`，并把原始资料保留在受控位置。

## 文档状态

- `draft`：草稿，尚未通过审核；
- `review`：等待人工审核；
- `published`：可作为正式团队知识引用；
- `archived`：已保留但不再维护。

对于 AI 生成内容，尽可能保留 `generated` 元数据；纯人工页面可以省略该字段。
